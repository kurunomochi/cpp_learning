F01. 从 main 的每个符号开始：声明、初始化与输出

你需要先建立的三个概念

源代码是写给编译器看的文本；程序是编译链接后的产物；进程是程序正在运行的一次实例。修改 .cpp 不会自动改变正在运行的旧进程。每次实验都要重新构建、停止旧程序、运行新程序。

对象是存放数据、具有类型和生命周期的实体。变量是我们命名对象的一种方式。int count{0}; 可以从左往右读成“创建一个名为 count 的 int 对象，并用 0 初始化”。不是先随便放一个东西、以后再决定类型。

文件：lessons/foundations/01_values.cpp

cpp#include <iostream>
#include <string>
int main() {
    int count{};                         // 初始化为 0
    const int limit{3};                  // 初始化后不再修改
    std::string title{"Learn C++"};      // 字符串对象拥有内容
    count = count + 1;                   // 给现有对象赋新值
    std::cout << title << '\n';
    std::cout << "count=" << count << ", limit=" << limit << '\n';
    return count == 1 ? 0 : 1;
}

逐行读懂：#include <iostream> 让当前翻译单元看到输入输出设施的声明；它不是运行时“导入另一个程序”。<string> 提供字符串类型。int main() 是普通控制台程序入口；空括号表示此形式没有参数；花括号圈定函数体。std:: 表示从标准库命名空间寻找名字。std::cout << ... 使用输出流的插入运算符，'\n' 是换行字符。大多数语句以分号结尾，函数体末尾不需要额外分号。

count{} 是值初始化，int 得到 0；count = count + 1 是赋值，左侧是被修改的对象，右侧先计算新值。const int limit{3} 仍然占有一个带类型的值，只是不能再通过这个名字修改。std::string 会管理自己的内存，不需要手动为结尾的零字符留位置。

预期输出：

textLearn C++
count=1, limit=3

最后的 条件 ? 值1 : 值2 是条件表达式。return count == 1 ? 0 : 1; 相当于“检查成功返回 0，否则返回 1”。注意 == 比较是否相等，= 执行赋值。main 的返回值交给操作系统；普通函数返回值交给调用者。

初始化不是一个无关紧要的风格问题

cpp// 片段
int a{};         // a 是 0
int b{10};       // b 是 10
int c = 10;      // 也是初始化，不是先创建再赋值
// int d;        // 自动存储期的内置整数没有被初始化，不要读取它
// int e{3.8};   // 故意错误：列表初始化拒绝这里的窄化

先普遍使用 {} 帮助防止意外窄化，但不要把它当万能语法：容器有 initializer_list 重载，std::vector<int> a{3, 7} 是两个元素 3 和 7，std::vector<int> b(3, 7) 是三个 7。遇到一个类型先看它选中了什么构造函数。

练习：增加 const std::string owner{"me"};，输出 owner、title、count；再让 count 从 0 变成 2，调整检查条件。参考思路：输出可以连续使用 <<；两次自增或一次 count += 2 都可以。若只修改输出文字而没修改变量值，程序自检应该失败。

过关标准：不看答案写出能输出两行文字的程序；能解释初始化与赋值的区别；知道终端报的“找不到程序”和编译器报的“缺少分号”不是同一类问题。

F02. 数字与表达式：类型决定计算结果

类型、范围和单位一起思考

bool 表示真假；char 表示一个字符编码单元；int 是常用整数；double 是常用浮点类型；std::int64_t 在提供它的平台上是恰好 64 位的有符号整数。不要把 int 一律当 32 位保证，查看 std::numeric_limits<int>；也不要把 long 当跨平台固定宽度整数。

后端中端口、任务 ID、字符串长度、时间各有范围和单位。即使都能存进一个整数，也不表示可以互换。例如 HTTP 的 Content-Length 是字节数，UTF-8 中文标题的字节数不等于显示字符数。

文件：lessons/foundations/02_numbers.cpp

cpp#include <cmath>
#include <iostream>
#include <limits>
#include <optional>
std::optional<int> checked_add(int a, int b) {
    const int high = std::numeric_limits<int>::max();
    const int low = std::numeric_limits<int>::min();
    if ((b > 0 && a > high - b) || (b < 0 && a < low - b))
        return std::nullopt;
    return a + b;                        // 检查通过后才执行加法
}
int main() {
    const int done{2};
    const int total{3};
    const double ratio = static_cast<double>(done) / total;
    const auto sum = checked_add(7, 5);
    const auto overflow = checked_add(std::numeric_limits<int>::max(), 1);
    std::cout << "integer=" << done / total << '\n';
    std::cout << "ratio=" << ratio << '\n';
    std::cout << "sum=" << sum.value_or(-1) << '\n';
    std::cout << "overflow=" << std::boolalpha << !overflow.has_value() << '\n';
    return sum == 12 && !overflow && std::abs(ratio - 2.0 / 3.0) < 1e-9 ? 0 : 1;
}

输出的关键值为 integer=0、ratio=0.666667、sum=12、overflow=true。2 / 3 两边是整数，先做整数除法，结果是 0；把结果赋给 double 也只能得到 0.0。先把一个操作数转换成 double，另一边才参与浮点运算。

static_cast<double>(done) 明确表达有意转换。强制转换不会自动检查越界，例如浮点转整数时仍要先保证可表示；不要为了消除警告随便加 cast。sizeof(T) 给的是对象大小，单位是 C++ 字节，一个字节有多少位可查 CHAR_BIT。

常见运算符及阅读顺序

表达式 含义 典型错误
a + b、a * b 算术 结果超出类型范围
a / b、a % b 商、整数余数 b 为 0；误把整数除法当小数
a == b、a != b 相等、不等 写成赋值
a < b、a >= b 大小比较 写 0 < x < 10
a && b、`a b`
!ok 逻辑取反 误以为 optional 的真假是内部 bool
++n、n++ 都使 n 加 1 同一表达式多次修改同一变量

区间应写成 x > 0 && x < 10。&& 左侧为 false 就不计算右侧，所以 pointer != nullptr && pointer->ready() 可以在右侧访问之前检查空指针；它不能保护悬空指针。优先级拿不准就加括号，避免写需要依靠细微求值顺序才能理解的表达式。

为什么必须在加法之前检查溢出

有符号整数溢出是未定义行为，不能先算出溢出结果再检查它。checked_add 的逻辑是：正数相加前检查 a > 最大值 - b；负数相加前检查 a < 最小值 - b。检查表达式本身也要在范围内。本例返回 optional<int>，有值表示成功，nullopt 表示无法表示；F11 会完整解释。

无符号整数按模运算也不等于业务合法。std::size_t size{0}; --size; 会绕到很大的值，所以不要用 i >= 0 配合无符号 i 写倒序循环。使用反向迭代器，或写 for (std::size_t i = values.size(); i > 0; --i) { use(values[i - 1]); }。

浮点不是十进制实数的精确替身。钱通常使用整数最小货币单位或合适的十进制库；容许误差比较要依据业务量纲和相对/绝对误差选择，例子的 1e-9 只是这个比值的测试阈值。

练习与参考：给 checked_add 增加最小值加 -1、最大值加 0、-7 加 5 三个调用，预期分别无值、最大值、-2。解释为什么把 static_cast<double> 移到整个 done / total 外面不能修正结果。F11 会用相同边界意识处理端口输入。

F03. 控制流：跟着状态一步一步执行

分支决定走哪一条路

cpp// 片段：score 已经是一个 int
if (score >= 90) {
    std::cout << "excellent\n";
} else if (score >= 60) {
    std::cout << "pass\n";
} else {
    std::cout << "retry\n";
}

从上到下检查条件，一旦命中就不进入后面的分支。通常保留花括号，即使暂时只有一行；否则以后加日志时容易把新语句放到条件之外。范围外输入应先拒绝，再做正常分类。

文件：lessons/foundations/03_control.cpp

cpp#include <iostream>
#include <vector>
int main() {
    const std::vector<int> ids{1, 2, 3, 4, 5};
    int sum{};
    for (const int id : ids) {
        if (id == 2) continue;           // 跳过当前这轮
        if (id > 4) break;               // 结束整个循环
        sum += id;
    }
    int retries{3};
    while (retries > 0) {
        --retries;                       // 循环状态必须能够前进
    }
    const bool accepted = sum == 8 && retries == 0;
    std::cout << "sum=" << sum << ", retries=" << retries << '\n';
    if (accepted) std::cout << "accepted\n";
    return accepted ? 0 : 1;
}

手工列出状态表比反复盯着代码更有效：

id 行为 sum
1 加入 1
2 continue 1
3 加入 4
4 加入 8
5 break 8

输出 sum=8, retries=0 和 accepted。continue 进入下一轮，break 退出最近一层循环；都不会直接退出 main。return 才退出当前函数。嵌套循环时，不要以为一个 break 会退出所有层。

三种循环怎样选

遍历容器优先 for (const auto& item : items)。需要下标时写普通 for；每轮先判断条件，再执行循环体，最后执行递增语句。while 适合“直到输入结束”；do ... while 至少执行一次，注意末尾分号。

cpp// 独立输入循环片段，需要 <iostream>、<string>
std::string line;
while (std::getline(std::cin, line)) {
    if (line == "quit") break;
    if (line.empty()) continue;
    std::cout << "received: " << line << '\n';
}

getline 读取一整行并去掉换行分隔符。不要先检查 eof() 再读取，EOF 状态通常是在读取失败后才被设置。std::cin >> number 遇到非法文本会进入失败状态，后续读取不会自动恢复；在 CLI 教学中先读整行再用 F11 的严格解析更容易控制错误。

如果混用 >> 与 getline，前者可能留下换行，后者马上读到空行；可以统一用 getline，或理解后用 ignore 清理。不要盲目把空行当用户真的没输入。

switch 适用于整数或枚举的离散值；每个 case 常用 break 结束。不写 break 会贯穿到后面的 case，需要这种行为时使用 [[fallthrough]]; 明确表达；std::string 不能直接作为 switch 条件。

练习：写一个循环接受 add、list、quit 三种命令，其余输出 unknown。先不存储任务。参考流程：getline → 判断 quit → 判断 add/list → 其他分支。输入结束时自然退出，不要 while(true) 后忘记 EOF 分支。完成后你已写出 CLI 主循环的骨架。

F04. 函数、作用域与契约：把问题拆成能验证的步骤

看函数时问四件事

输入是什么、结果是什么、是否修改外部对象、失败怎样表达。这四个问题就是一个小型契约。int add(int a, int b) 还没有说清楚允许多大的 a/b，因此真实输入需要边界规则。

文件：lessons/foundations/04_functions.cpp

cpp#include <iostream>
#include <string>
#include <string_view>
int increment_copy(int value) { return ++value; }
void increment(int& value) { ++value; }
bool valid_title(std::string_view title) {
    return !title.empty() && title.size() <= 200;
}
std::string make_label(int id) {
    return "task-" + std::to_string(id);   // 按值返回，结果有自己的生命周期
}
int main() {
    int count{3};
    const int changed_copy = increment_copy(count);
    const bool copy_unchanged = count == 3;
    increment(count);
    const auto label = make_label(count);
    std::cout << label << '\n';
    return changed_copy == 4 && copy_unchanged && count == 4 && valid_title(label) && !valid_title("") ? 0 : 1;
}

输出 task-4。调用 increment_copy(count) 时创建参数 value，它有自己的整数值。返回的 4 存进 changed_copy，原始 count 仍然为 3。increment(int& value) 的参数是调用者对象的别名，因此改变了 count。void 表示函数不返回一个结果值，不表示它没有效果。

valid_title 这里只检查非空及最多 200 字节，未实现最终服务的控制字符等完整规则；练习模型不要被误当生产校验。make_label 返回 string 值，调用者得到一个有自身生命周期的对象。这比返回局部变量引用安全。

局部变量能活到哪里

cpp// 故意错误：不要编译进正常项目
const std::string& broken() {
    std::string local{"gone"};
    return local; // 返回后 local 已销毁，引用悬空
}

作用域决定名字在哪里可见；生命周期决定对象什么时候存在。两者相关但不同：动态对象可以超过创建它的函数调用而存活；某个引用名仍可见时，被引用对象可能已经被销毁。F08 会用所有权描述这种差别。

名字被局部同名变量遮蔽也会制造误会；开启 -Wshadow 可以帮助发现。函数应短到能在脑中追踪局部状态，不要让“解析输入、写数据库、发 HTTP、打印日志”全部塞进同一个函数。

声明、重载与默认参数

cpp// 头文件中的声明片段
int clamp_count(int value, int maximum = 100);

// .cpp 中的定义片段：默认值通常只在声明处写一次
int clamp_count(int value, int maximum) {
    if (value < 0) return 0;
    return value > maximum ? maximum : value;
}

调用处需要先看见声明，链接时需要找到定义。函数可以按参数类型或数量重载，但不能只按返回类型重载。参数名称可以不同，类型、命名空间、const 等影响匹配的部分必须一致。默认参数在调用处使用，不是一个额外重载函数。

递归是函数直接或间接调用自己，需要终止条件，每次调用通常消耗调用栈。处理简单任务列表用循环更直接；不要为展示技巧引入深递归和栈耗尽风险。

练习：独立写 bool valid_limit(int value)，仅 1～100 返回 true。使用 -1、0、1、100、101 验证。参考实现：return value >= 1 && value <= 100;。然后拆出 .hpp/.cpp，故意漏编译 cpp 观察链接错误；这个实验连接主教材第 2 章和 CMake C04。

F05. 引用、指针、const、auto：先说明是否拥有和是否修改

文件：lessons/foundations/05_references.cpp

cpp#include <iostream>
#include <string>
int main() {
    std::string title{"draft"};
    auto copy = title;                   // 一个新的 string
    auto& alias = title;                 // title 的别名
    const auto& view = title;            // 不允许通过 view 修改 title
    copy += " copy";
    alias += " ready";
    std::string* pointer = &title;       // 保存地址，不拥有对象
    if (pointer != nullptr) pointer->append("!");
    pointer = nullptr;                  // 不会销毁 title
    std::cout << "copy=" << copy << '\n';
    std::cout << "original=" << view << '\n';
    return copy == "draft copy" && title == "draft ready!" && pointer == nullptr ? 0 : 1;
}

输出 copy=draft copy 和 original=draft ready!。把纸上画成两格：title 一格、copy 一格；alias 和 view 都画箭头指向 title，pointer 存储 title 的地址。把 pointer 设成 nullptr 只改变箭头，不影响 title。

同一个符号在不同位置有不同含义

写法 含义
int& ref = value 声明左值引用，绑定现有对象
&value 取地址
int* ptr = &value 声明指针并存入地址
*ptr 解引用，访问指向对象
ptr->member 等价于 (*ptr).member
a & b 整数按位与，和引用声明无关

引用必须初始化，之后不能改绑；ref = another 是给被引用对象赋值。引用本身没有正常的“空值”状态，但一样可能悬空。指针可以为 nullptr、可以改指向、可以悬空；非空不等于有效。访问前需要知道对象还活着，而不只是检查非空。

const 约束的是哪一层

cpp// 片段
int value{3};
const int* p = &value;     // 通过 p 不能修改 value，p 自身能改指向
int* const q = &value;     // q 不能改指向，通过 q 可以修改 value
const int* const r = &value; // 两方面都不允许

const 不意味着底层对象永不变化，例子中的 value 仍可经其他可写途径修改；也不意味着线程安全。不要用 const_cast 绕过接口约束，如果原对象确实是 const，再写它是未定义行为。

auto 不是“无类型变量”

auto 在编译期推导出固定类型。普通 auto x = expression 常会去掉顶层 const 和引用并创建值；需要引用就明确写 auto& 或 const auto&。例如 const int n{3}; auto a = n; 的 a 可以修改；const auto& b = n; 借用 n。

遍历 vector<Task> 时 auto task 每轮复制一个任务，修改它不会更新容器；auto& task 修改原任务；const auto& task 只读且避免复制。也不能一味避免所有复制：复制小整数、string_view 很便宜，按值返回结果常更安全。

函数参数的一套起点规则：小标量按值；较大对象只读时用 const T&；明确需要修改调用者用 T&；可选的非拥有对象可以用 T*；需要转移所有权时按值接收 unique_ptr<T>。不要把一个裸指针的出现自动解释成“应该 delete”。

F06. 数组、字符串与 vector：从长度和失效规则入手

文件：lessons/foundations/06_containers.cpp

cpp#include <array>
#include <iostream>
#include <string>
#include <vector>
int main() {
    const std::array<int, 3> ports{8080, 8081, 8082};
    std::vector<std::string> tasks{"read", "code"};
    tasks.push_back("test");
    for (auto& title : tasks) title += "!";
    for (const auto& title : tasks) std::cout << title << '\n';
    std::cout << "port=" << ports.at(0) << ", size=" << tasks.size() << '\n';
    return tasks.size() == 3 && tasks.at(1) == "code!" ? 0 : 1;
}

输出 read!、code!、test!，最后 port=8080, size=3。std::array<int, 3> 的元素数量是类型的一部分，创建后不变；std::vector<std::string> 的大小可在运行期改变。容器对象自身即使是局部变量，也可以管理另外分配的动态存储，不要把“局部变量”理解成“所有数据都必须在栈内”。

size、capacity、reserve、resize 要分清

cpp// 片段
std::vector<int> ids;
ids.reserve(10);  // 预留至少 10 个元素的容量，size 仍然是 0
// ids[0] = 1;    // 错误：不存在第 0 个元素
ids.push_back(1); // size 变为 1
ids.resize(3);    // size 变为 3，新增加的 int 元素值初始化为 0

operator[] 不负责边界检查，越界访问是未定义行为；.at(index) 越界抛出 out_of_range。性能敏感的已证明范围内循环可以用 []，外部输入索引需要验证。front()、back() 也要求容器非空。

vector 扩容时可能搬迁全部元素，先前拿到的引用、指针、迭代器因此失效。reserve 能减少搬迁，但不能承诺以后所有修改都安全；erase 会使删除位置及之后的迭代器/引用失效。不保存容器内部地址，改保存任务 ID 并重新查找，常更适合业务代码。

字符、字符串、字符数组不是同一回事

'a' 是 char，"a" 是含结尾零字符的字符串字面量数组，std::string{"a"} 是拥有内容的字符串对象。std::string 可以包含内部零字节，size 记录实际字节数量；交给只依赖结尾零字符的 C API 时可能被截断。

std::string_view 是非拥有视图，通常可理解为指针加长度。适合函数同步只读参数，不能延长字符串寿命。std::string_view v = std::string{"temporary"}; 在语句结束后会悬空。对 view 切片也不保证末尾有零字符，不能无条件把 view.data() 当 C 字符串。

原始数组 int items[3] 在很多表达式中会退化成指针，函数参数 int items[] 不携带数组长度。优先 array、vector；只读连续区间参数用 std::span<const int>，但 span 同样不拥有元素，也不能阻止生命周期结束。

map 与 unordered_map 什么时候再学

vector 适合连续遍历和小型任务列表；map 保持按键排序，常见查找复杂度对数级；unordered_map 平均常数级查找但不保证遍历顺序，最坏情况也不是常数级。map[key] 在 key 不存在时会插入默认值；只读查找使用 find/contains，避免查询动作改变数据。

练习：给 F06 删除最后一个元素，再验证 size 为 2；尝试 .at(10) 并捕获异常。参考：pop_back() 要求非空；异常使用 catch (const std::out_of_range& e)，e.what() 返回说明。不要为了“看看会怎样”在正常测试中执行 [] 越界。

F07. struct、class 与构造函数：让对象一直满足规则

数据对象和维护规则的对象

struct 与 class 的主要语言区别是默认成员访问权限和默认继承访问权限。可以用 struct 表达简单数据记录，用 class 隐藏不应随意改动的状态。它们都可以有构造函数、成员函数、析构函数和模板。

文件：lessons/foundations/07_classes.cpp

cpp#include <iostream>
#include <stdexcept>
#include <string>
#include <utility>
class Task {
public:
    explicit Task(std::string title) : title_(checked(std::move(title))) {}
    const std::string& title() const noexcept { return title_; }
    bool completed() const noexcept { return completed_; }
    void complete() noexcept { completed_ = true; }
    void rename(std::string title) { title_ = checked(std::move(title)); }
private:
    static std::string checked(std::string title) {
        if (title.empty()) throw std::invalid_argument("empty title");
        return title;
    }
    std::string title_;
    bool completed_{false};
};
int main() {
    Task task{"learn"};
    task.complete();
    bool rejected{false};
    try { task.rename(""); }
    catch (const std::invalid_argument&) { rejected = true; }
    std::cout << task.title() << ": " << std::boolalpha << task.completed() << '\n';
    return rejected && task.title() == "learn" && task.completed() ? 0 : 1;
}

输出 learn: true。公开函数形成对象可使用的操作；private 成员阻止调用者直接把 title_ 改为空串。构造函数没有返回类型，它先初始化成员，随后才执行函数体。explicit 阻止这里某些隐式转换；你仍可以明确写 Task{"learn"}。

const std::string& title() const noexcept 分为三段：返回类型是只读引用；函数后面的 const 说明不通过 this 修改普通成员；noexcept 声明异常不应逃出。返回引用只在 Task 及其成员仍有效期间可用；不能把临时 Task 的 title 引用长期保存。

初始化列表和赋值的差别

title_(checked(std::move(title))) 在成员创建时提供初始值。若在函数体里写 title_ = title;，则 title_ 已先默认构造，再被赋值；const 成员、引用成员和无默认构造的成员尤其需要初始化列表。

成员实际按类内声明顺序初始化，与初始化列表的书写顺序无关。成员析构顺序相反。让列表保持与声明一致，避免依赖尚未初始化的成员。

不变量与失败后的状态

本例的不变量是“title_ 不为空”。构造失败时不会产生一个可供调用者使用的无效 Task；rename 先检查新的字符串，再赋值，所以非法改名不会破坏旧标题。测试先调用非法改名，再确认标题还是 learn，验证的就是这个性质。

static 成员函数没有 this 指针，因此 checked 不直接访问某一个 Task 的成员。this 指向当前对象；同名参数可能遮蔽成员，所以示例通常用尾部下划线区分成员变量。

暂时不要急着把所有东西改成继承

服务器“拥有一个仓库”用成员对象表达，是组合。若以后需要不同仓库实现可以再考虑抽象接口。用基类指针销毁派生对象时基类通常需要 virtual 析构函数；把派生对象按值传给基类参数会发生切片。当前项目主要依赖组合，理解这些坑即可，不必先建复杂继承树。

练习：给 Task 增加 reopen()，使 completed_ 变为 false，并增加成功后检查。再把标题规则加强为不超过 200 字节。参考：在 checked 中增加边界检查，构造和 rename 同时获得相同规则；不要在两个地方复制一份校验。

F08. 生命周期、RAII、复制与移动：资源必须有明确的负责人

从析构顺序观察资源管理

文件：lessons/foundations/08_lifetime.cpp

cpp#include <iostream>
#include <memory>
#include <string>
#include <utility>
struct Trace {
    explicit Trace(std::string label) : label(std::move(label)) {
        std::cout << "open " << this->label << '\n';
    }
    ~Trace() { std::cout << "close " << label << '\n'; }
    Trace(const Trace&) = delete;
    Trace& operator=(const Trace&) = delete;
    std::string label;
};
int main() {
    Trace outer{"outer"};
    {
        auto first = std::make_unique<Trace>("resource");
        auto second = std::move(first);  // 转移指针的所有权，不移动 Trace 对象
        if (first || !second) return 1;
        std::cout << "owner moved\n";
    }                                   // second 析构，释放 Trace
    std::cout << "leaving main\n";
}                                       // outer 析构

预期输出依次为：

textopen outer
open resource
owner moved
close resource
leaving main
close outer

outer 在 main 的局部作用域中；first/second 在内部作用域中。内部作用域结束时 second 的析构函数释放它拥有的 Trace 对象，first 已经没有对象。注意 std::move(first) 没有把 Trace 移到另一个内存位置，而是把 unique_ptr 的所有权转给 second。

RAII 的核心是把资源的获取与释放绑定到对象生命周期。对象正常离开作用域或因异常展开栈时，其已构造完成的成员和局部对象会被清理。异常前尚未完成构造的对象不会调用自己的完整析构函数，但已成功构造的子对象会清理。

这不覆盖断电、强制杀进程、std::abort 等所有退出方式；数据库持久化和事务另有责任。C++ 没有自动保证你任意写的资源管理代码都正确，因此尽量让标准库对象做拥有者。

自动存储期、动态存储期和所有权

局部 string、vector、unique_ptr 离开作用域自动析构；它们可以拥有动态分配的资源。手工 new 得到的对象若没有匹配释放会泄漏；两次 delete 是错误。优先直接放对象，只有需要动态生命周期等理由才使用 make_unique。裸指针和引用主要表达借用，借用者不负责 delete。

文件同样可用 RAII：std::ifstream input{"config.txt"}; 构造时打开，析构时关闭。打开失败通常要检查流状态，默认不会自动抛异常。mutex 则由 lock_guard 在作用域内持锁，异常路径也会解锁。

复制和移动不是两个速度按钮

复制通常创建独立的逻辑值；移动允许目标接管源对象的资源。std::move(x) 只是把表达式转换为可参与移动重载选择的形式，本身不搬运资源；如果没有合适的移动操作，也可能发生复制。

unique_ptr 的移动后状态明确为空；string/vector 的移动后对象通常仍有效但状态未指定，除非某个操作有更强保证。不要断言“所有移动后的字符串一定为空”。可以销毁、重新赋值，调用其他操作时必须满足其前置条件。

const std::string source; std::move(source) 得到 const 右值，常见 string 移动构造不能接收可修改资源的 const 源，因此可能选择复制。不要到处加 std::move，尤其返回本地对象常直接 return value;，让复制消除/隐式移动机制工作。

Rule of Zero 与自定义析构的代价

让成员使用 string、vector、unique_ptr 等正确的资源拥有者，通常无需自己实现复制、移动、析构，这叫 Rule of Zero。只要自己开始管理裸资源，就必须一起审视复制构造、复制赋值、移动构造、移动赋值和析构，即 Rule of Five。

示例 Trace 删除复制，是为了避免读者误以为打印 open/close 的模拟资源可以随便复制。最终仓库也删除复制，因为一个连接不应该被两个对象误以为自己独占关闭。

shared_ptr 表达共享所有权，用引用计数决定何时释放；计数控制块支持多线程并不意味着被管理对象的成员线程安全。互相持有 shared_ptr 会形成环，可使用 weak_ptr 表达不拥有的观察关系。没有共享生命周期需求时不使用它。

练习：在输出 owner moved 后抛出 runtime_error，并在 main 的外层 try/catch 接住，预测 close 行的顺序。参考：内部资源先清理，再清理 outer（若 outer 位于该 try 内），最后进入 catch。异常练习放到临时副本，不改默认必须返回成功的测试。

F09. 迭代器、算法与 lambda：读懂回调的关键准备

文件：lessons/foundations/09_algorithms.cpp

cpp#include <algorithm>
#include <iostream>
#include <string>
#include <vector>
struct Task { int id; std::string title; bool done; };
int main() {
    std::vector<Task> tasks{{3, "test", false}, {1, "read", true}, {2, "code", false}};
    std::ranges::sort(tasks, {}, &Task::id);
    const int wanted{2};
    const auto it = std::ranges::find_if(tasks, [wanted](const Task& task) {
        return task.id == wanted;
    });
    if (it == tasks.end()) return 1;
    it->done = true;
    const auto removed = std::erase_if(tasks, [](const Task& task) { return task.done; });
    // erase 后不再使用 it，它可能已经失效。
    std::cout << "removed=" << removed << ", left=" << tasks.size() << '\n';
    return removed == 2 && tasks.front().id == 3 ? 0 : 1;
}

输出 removed=2, left=1。Task 是简单聚合，花括号按字段顺序初始化。sort 的 {} 表示默认比较器，&Task::id 是成员指针形式的投影，表示按 id 比较。不是对指针地址排序，也不是每次排序都复制一个容器。

迭代器是位置，end 是边界

begin 指向第一个元素，end 指向最后一个元素之后的位置。区间写成 [begin, end)，左闭右开；空容器 begin 等于 end。find_if 返回 end 表示没找到，在判断前不能 *it 或 it->title。不能因为程序某次没崩溃就认为解引用 end 合法。

erase_if 返回删除的数量。传统 remove_if 只把保留元素往前重排并返回逻辑末端，不缩小容器；搭配 erase 才真正改 size。C++20 的 erase_if 更直接，仍必须遵守失效规则。

lambda 按“捕获、参数、函数体”拆开

cpp[wanted](const Task& task) { return task.id == wanted; }

[wanted] 把 wanted 的值保存进闭包；const Task& task 是每次算法调用给它的参数；函数体返回匹配与否。lambda 可以理解成带有 operator() 的匿名函数对象。它能携带状态，因此适合网络路由回调。

[&wanted] 借用外部 wanted，外部对象必须活得更久。[] 不捕获局部变量；[=] 按值隐式捕获，[&] 按引用隐式捕获。教学和长期保存的回调优先显式列出捕获，便于审查生命周期。捕获 this 保存的是指针，不会延长当前对象寿命。

默认 lambda 的按值捕获成员不能在函数体中修改；mutable 允许修改闭包内部副本，并不会因此修改原始值。需要返回闭包时可用 auto 返回类型；std::function 是一种类型擦除包装，可能带来分配和间接调用，并非所有 lambda 都必须放进去。

ranges 的惰性不是缓存

cpp// 片段，需要 <ranges>；tasks 必须在整个遍历期间有效
auto pending = tasks | std::views::filter([](const Task& task) { return !task.done; });
for (const auto& task : pending) std::cout << task.title << '\n';

view 通常在遍历时筛选，不一定提前生成新容器；它可能借用原容器。不要返回借用本地 vector 的 view。遍历期间修改底层容器、修改影响筛选的字段，需要认真查看迭代器和视图规则；初学时优先先计算、后修改。

练习与参考：改为保留未完成任务并统计数量；用 count_if 可以统计而不删除，循环统计也可以。说明 HTTP 中的 [&repository] 为什么要求仓库活到所有请求处理结束，这就是从算法回调走向服务器回调的连接点。

F10. 模板、头文件与命名空间：看懂库的声明

文件：lessons/foundations/10_templates.cpp

cpp#include <concepts>
#include <iostream>
#include <string>
#include <utility>
template<class T> class Box {
public:
    explicit Box(T value) : value_(std::move(value)) {}
    const T& get() const noexcept { return value_; }
private:
    T value_;
};
template<std::integral T> constexpr bool positive(T value) {
    return value > T{0};
}
static_assert(positive(3));
static_assert(!positive(-1));
int main() {
    const Box<std::string> title{"templates"};
    const Box<int> id{7};
    std::cout << title.get() << ": " << id.get() << '\n';
    return positive(id.get()) ? 0 : 1;
}

输出 templates: 7。template<class T> 表示定义一个类型参数，Box 与 Box 是不同的类型；这里的 class 也可以写 typename，不要求 T 一定是用户定义的 class。value_ 的类型在具体实例化时确定，不是在运行时随便变化。

普通函数与函数模板

把 T 替换为具体类型可以帮助初学阅读，但编译器的真实处理包含名称查找、约束检查等规则，不是简单文本替换。模板类型推导可能无法在多个不同参数类型间选出一致的 T；不要把所有失败都用强转盖住。

template<std::integral T> 限制 T 满足整型概念。它比无约束模板产生更贴近使用要求的错误。positive(1.5) 会因约束不满足而编译失败；这是预期的接口保护。concept 检查表达式和类型条件，不会自动证明业务意义或线程安全。

constexpr 表示在满足条件的上下文中可以常量求值，普通运行期输入仍然可以调用。static_assert 在编译期要求条件为真，和运行时 assert 不一样。const 主要限制修改，不保证某个值一定能用于编译期计算。

模板定义通常放头文件

使用点常需要看见模板定义才能实例化。如果只在头文件声明 Box 的成员，把所有模板实现藏到普通 cpp，另一个翻译单元使用新类型时可能出现链接错误。显式实例化可以为固定类型解决部分问题，但初学时先把小模板完整定义放头文件。

头文件要自包含：使用 string 就包含 string，不依赖使用者碰巧先 include 别的头。普通非 inline 函数定义放 cpp，避免重复定义；模板和类内定义的成员函数有相应的规则允许头文件组织。头文件全局变量可使用 C++17 inline 变量或 extern 声明加 cpp 定义，不能随意重复定义。

#pragma once 是常见编译器支持的写法；传统 #ifndef include guard 是另一种。它们防止同一翻译单元重复包含，不会把多个 cpp 自动变成一个翻译单元。

命名空间、enum class 与别名

cpp// 片段：可放在 domain.hpp 的 namespace task 内
enum class Status { pending, done };
using TaskId = std::int64_t; // 需要 <cstdint>；别名不是新的独立强类型

枚举使用 Status::pending，避免名字混进外部作用域。不要在公共头文件中写 using namespace std;，否则会改变所有包含者的名称查找环境。cpp 内匿名命名空间可隐藏只供当前翻译单元使用的辅助实现。

练习：把 Box 放进 box.hpp，用两个 cpp 分别实例化 Box 和 Box，一起链接。故意调用 positive(1.5) 阅读第一条约束诊断，再恢复。参考：不需要在 CMake 中为每个模板实例添加一个 target，两个 cpp 作为同一 executable 的源文件即可。

F11. optional、异常和严格输入：错误是接口的一部分

文件：lessons/foundations/11_errors.cpp

cpp#include <charconv>
#include <iostream>
#include <optional>
#include <string_view>
#include <system_error>
std::optional<int> parse_port(std::string_view text) {
    if (text.empty()) return std::nullopt;
    int value{};
    const auto [end, error] = std::from_chars(text.data(), text.data() + text.size(), value);
    if (error != std::errc{} || end != text.data() + text.size()) return std::nullopt;
    if (value < 1 || value > 65535) return std::nullopt;
    return value;
}
int main() {
    for (const auto input : {"8080", "80x", "0", "65536", "", "99999999999999999999"}) {
        const auto value = parse_port(input);
        std::cout << '[' << input << "] -> ";
        if (value) std::cout << *value << '\n';
        else std::cout << "invalid\n";
    }
    return parse_port("8080") == 8080 && parse_port("65535") == 65535 &&
        !parse_port("80x") && !parse_port("0") && !parse_port("65536") &&
        !parse_port("") && !parse_port("99999999999999999999") ? 0 : 1;
}

只有 [8080] -> 8080 成功，其他展示输入都输出 invalid。解析必须满足三层条件：语法转换成功、整个输入被消耗、数值处于业务范围。80x 前缀能转成 80，不等于输入是合法端口。

from_chars 返回结束指针和 error code，示例用结构化绑定 const auto [end, error] 拆开。它不会像部分流输入那样自动跳过前导空格，也不会接受所有习惯写法；本课程有意使用严格十进制语法，正号、空白等接受策略需要主动设计。

optional 的真假是“有没有值”

cpp// 片段，需要 <optional>
std::optional<bool> completed{false};
if (completed) {
    // 能进入这里，因为它有值；*completed 才是 false
}

nullopt、值 false、值 true 是三种不同状态，恰好适合 PATCH：不传 completed 不修改，传 false 取消完成，传 true 标为完成。先检查存在再 *optional；.value() 在无值时抛 bad_optional_access；value_or(default) 返回实际值或默认值，不适合所有错误都静默吞掉的场景。

什么时候用异常

用户输错端口很常见，optional 能直接表达失败；构造数据库仓库打不开文件时，无法形成有效对象，抛异常可以沿调用栈交给边界处理。当前 C++20 项目没有使用 C++23 的 std::expected；不需要为了读教材先升级标准。

cpp// 片段，需要 <exception>、<iostream>
try {
    run_server(); // 需要你自己的声明与实现
} catch (const std::exception& error) {
    std::cerr << error.what() << '\n';
    return 1;
}

按 const 引用捕获，避免复制和切片。具体异常的 catch 放一般异常之前。异常跨越作用域时清理局部资源，所以 RAII 与异常配合；不要每层都 catch 后返回“成功”。HTTP 边界应把已知输入错误映射到适当状态码，内部异常记录日志并返回一般错误，避免把 SQL/文件路径暴露给客户端。

noexcept 不是“忽略异常”：异常逃出 noexcept 函数会触发终止。析构函数应避免抛异常，尤其已经在异常展开时；资源关闭失败需要单独的显式操作/日志策略，而非任意在析构中 throw。

cpp// 片段，需要 <fstream>、<string>、<stdexcept>
std::ifstream input{"settings.txt"};
if (!input) throw std::runtime_error("cannot open settings.txt");
std::string line;

}

相对路径按当前工作目录解析，不是按 cpp 文件位置解析；这是 tasks.db “不见了”的常见原因。重要输出还需检查写入/flush/关闭结果，不能只因文件曾成功打开就认为数据一定保存成功。

F12. 从语法读到服务器：对象关系、线程与学习验收

先用一个可结束的小程序理解共享状态

文件：lessons/foundations/12_threads.cpp

cpp#include <iostream>
#include <mutex>
#include <thread>
#include <vector>
int main() {
    int count{};
    std::mutex mutex;
    {
        std::vector<std::jthread> workers;
        for (int n = 0; n < 4; ++n) {
            workers.emplace_back([&count, &mutex] {
                for (int i = 0; i < 1000; ++i) {
                    std::lock_guard lock{mutex};
                    ++count;
                }
            });
        }
    }                                   // jthread 析构并 join，之后才能读取 count
    std::cout << "count=" << count << '\n';
    return count == 4000 ? 0 : 1;
}

输出 count=4000。count 和 mutex 比 workers 活得更久；线程闭包按引用捕获它们。每个线程执行 1000 次，四个线程理论上应得到 4000，但普通 ++count 是读、修改、写，不是天然原子操作。没有同步的并发访问构成数据竞争时，程序是未定义行为，不能只说“偶尔少加几次”。

lock_guard 构造时锁定，退出本轮作用域时解锁。一个锁保护的是约定的共享状态，所有访问者必须遵守约定；只给写入一侧加锁而读取不加，不会自动正确。本例最终读取发生在全部 join 后，已经没有工作线程在改它。

jthread 析构时请求停止并 join；本例工作函数没有接收 stop_token，所以不会因请求停止而提前结束，而是做完有限循环。若线程无限循环且不响应停止，析构仍可能一直等待。join 是等待完成，不是强行杀线程。

把陌生的真实声明逐段翻译

cpp// 摘自配套仓库的接口形式
[[nodiscard]] std::optional<Task> get(std::int64_t id);

[[nodiscard]] 提醒调用者不要随意丢弃结果；optional 表示任务可能不存在；Task 是按值返回的数据；int64_t 是 ID 类型。这个接口没有引用 HTTP 请求对象，所以仓库可以在核心测试中直接使用。

cpp// 概念片段：学习读捕获关系，完整路由见 src/http_api.cpp
server.Get("/api/tasks", [&repository](const httplib::Request& request,
                                      httplib::Response& response) {
    // request 是只读借用，response 是可修改借用；repository 也只是借用。
});

注册路由只保存回调，回调常在后来收到请求时执行。因此不能捕获注册函数中马上要销毁的局部仓库。主程序先构造 repository，再构造 server，正常反向析构有利于先清理服务器；还必须确保请求工作线程已停止，不能仅凭声明顺序就断言任何异步程序都安全。

一次请求的四层翻译

客户端给出 JSON 文本 → HTTP 层检查媒体类型、语法、字段 → 转为 C++ 数据对象 → 仓库在锁保护下绑定 SQL 参数并读写 → HTTP 层把结果转回 JSON 和状态码。你学的字符串、optional、引用、RAII 和异常，都分别参与其中。

不要一开始自己重写 HTTP 解析器或内存分配器来证明“懂底层”。先能解释库负责协议、自己负责业务规则的边界，再逐渐研究协议解析、异步 I/O 和内存模型。深度来自能证明行为，而不是每次都从零重写。
