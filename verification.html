本机环境

  • Windows 64 位；MSYS2 UCRT64 GCC 16.1.0。
  • CMake 4.4.3；Ninja 1.13.2。
  • CMake 找到的测试解释器为 Python 3.9.13；辅助脚本另用本机 Python 3.14.5 验证。
  • 固定依赖：cpp-httplib 0.61.0、nlohmann/json 3.12.0、SQLite 3.54.1。
  • SQLite 官方下载归档的 SHA3-256 与下载页公布值一致。

共 3 个 CTest 测试目标。80 项指 core_tests 与 HTTP 脚本内检查数量之和，不包含现代语言示例程序的额外检查；不是 80 个独立 CTest 目标。

HTTP 检查涵盖：CRUD、分页、UTF-8 标题、200/201 字节边界、非法 UTF-8、token 缺失/错误、错误 JSON/Content-Type/字段类型、超大请求体、非法和溢出 ID、缺失资源、SQL 注入样式文本、24 次并发创建、数据库锁冲突 503 与释放锁后恢复、服务重启后的数据保留。

另外执行：

  • CLI 的创建、列表、完成、删除流程。
  • 无效端口和非回环地址弱 token 配置被拒绝。
  • 在线备份 API、备份数据库读回核对、integrity_check。
  • priority 示例迁移执行两次，首次成功、再次不重复建列，旧数据默认值正确。
  • 小型负载脚本对 40 个 healthz 请求运行成功、无错误。数字只作为脚本功能验证，不作服务容量承诺。
  • configure/build/test presets 能被 CMake/CTest 正常识别。
  • HTML 阅读版已在本机无头 Chrome 中检查 1440×1080 和 390×844 布局，验证章节筛选、学习标记、明暗切换、页面脚本和本地文档链接。

构建目录位于交付包之外；交付包不包含本机生成的 EXE、DLL、任务数据库和测试日志。

未实机验证的范围

  • Linux GCC/Clang、MSVC、macOS 编译。
  • Linux ASan/UBSan、远程 GitHub Actions 工作流。
  • Docker 镜像、Compose、systemd 服务、Caddy 与真实域名 HTTPS。
  • Linux SIGTERM 优雅停机路径，以及真实公网网络故障/长连接/持续压力行为。

当前环境没有可用的 Docker/Linux 运行环境。上述内容已给出配置与目标机验收步骤，但没有标记为已部署或已通过。

Windows HTTP 测试使用进程 terminate 后重启，验证了数据持久化；它不等同于验证 Ctrl+C 或 Linux SIGTERM 的优雅停机。

工程边界

当前为单用户教学服务：同步 HTTP/1.1、固定线程池、一个由 mutex 保护的 SQLite 连接、共享 Bearer token。没有用户账号体系、对象级权限、完整限流、严格请求总截止时间、自动迁移、跨进程全局追踪 ID 和高可用能力。

priority 迁移脚本是毕业练习配套，仅改 schema；当前 C++ API 没有自动开启 priority 字段。教程中的概念片段和留给读者的练习不属于全部已编译的工程目标。
